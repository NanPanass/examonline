# ExamHub — ระบบสอบออนไลน์ (เวอร์ชัน backend เต็มรูปแบบ)

เวอร์ชันนี้แก้ปัญหาเชิงโครงสร้างของไฟล์ HTML เดี่ยวเดิม (localStorage เท่านั้น) โดยเพิ่ม
backend จริง (Node.js + Express + SQLite + Socket.io) ให้ครบตามที่ขอ:

- **บุคคลทั่วไปเข้าถึงข้อสอบได้โดยไม่ต้องมีบัญชี** — หน้าแรกเปิดให้ทุกคนดู/ทำข้อสอบชุดสาธารณะได้ทันที
  (ระบุชื่อที่ใช้แสดงผลอย่างเดียว) การสมัครสมาชิกจำเป็นเฉพาะตอนจะ "สร้าง/แก้ไขข้อสอบ" หรือ
  "เปิดห้องสอบสด" เท่านั้น
- **ข้อสอบรูปภาพ** — ทั้งโจทย์และแต่ละตัวเลือกใส่รูปได้ (อัปโหลดผ่าน `/api/upload`)
- **ห้องสอบสดแบบ Kahoot** — ผู้ใช้ที่ล็อกอินแล้วเปิดห้องจากชุดข้อสอบ (เฉพาะข้อปรนัย) ได้ PIN 6 หลัก
  เพื่อนพิมพ์ PIN + ชื่อเล่นเข้าร่วมได้เลยโดยไม่ต้องสมัครสมาชิก ตอบพร้อมกันแบบเรียลไทม์ มีคะแนนโบนัส
  ตามความเร็ว และกระดานผู้นำสดหลังทุกข้อ (ทดสอบ end-to-end แล้วในการพัฒนา)
- **เฉลยข้อสอบไม่เคยถูกส่งไปฝั่งเบราว์เซอร์ระหว่างทำข้อสอบ** — ตรวจให้คะแนนที่เซิร์ฟเวอร์ทั้งหมด
  (endpoint `/api/exam/:id/check` และ `/api/exam/:id/submit`) แก้จุดที่คอมเมนต์ในโค้ดเดิมบอกเองว่า
  "ไม่ใช่ความปลอดภัยจริง"
- **ล็อกอินจริง** — สมัคร/เข้าสู่ระบบด้วยอีเมล+รหัสผ่าน (bcrypt + JWT) แทนปุ่ม "จำลอง Google" เดิม

## อัปเดต: ย้ายฐานข้อมูลไป Turso + รองรับ deploy บน Vercel

เดิมไฟล์นี้ใช้ `better-sqlite3` เขียนไฟล์ `.db` ในเครื่อง ซึ่งใช้กับ Vercel ไม่ได้เพราะ
serverless ไม่มีดิสก์ถาวร ตอนนี้เปลี่ยนไปใช้ **Turso** (libSQL แบบเดียวกับ SQLite แต่เก็บบน
คลาวด์ผ่านเครือข่าย ให้ฟรี 5GB) แทน — โครงสร้างตาราง/คำสั่ง SQL เดิมทุกอย่างเหมือนเดิม
เปลี่ยนแค่ชั้นเชื่อมต่อ (`server/db.js`)

### 1. สมัคร Turso และสร้างฐานข้อมูล

```bash
# ติดตั้ง Turso CLI (ครั้งเดียว) แล้วสมัคร/ล็อกอิน
curl -sSfL https://get.tur.so/install.sh | bash
turso auth signup   # หรือ turso auth login ถ้ามีบัญชีแล้ว

# สร้างฐานข้อมูล
turso db create examhub

# ดึง URL และสร้าง token
turso db show examhub --url
turso db tokens create examhub
```
(หรือสมัครผ่านหน้าเว็บ https://turso.tech ก็ได้ ไม่จำเป็นต้องใช้ CLI)

คัดลอกค่า URL และ token มาใส่ในไฟล์ `.env` (ดูตัวอย่างที่ `.env.example`)

### 2. รันในเครื่องตัวเอง

```bash
npm install
cp .env.example .env   # แล้วแก้ค่าจริงในไฟล์ .env
npm start
```

เปิด `http://localhost:3000` — ผู้ใช้ที่สมัครสมาชิกคนแรกจะได้สิทธิ์ผู้ดูแลระบบ (admin) โดยอัตโนมัติ
ตาราง + ชุดข้อสอบตัวอย่าง 2 ชุดจะถูกสร้างในฐานข้อมูล Turso อัตโนมัติตอนรันครั้งแรก

### 3. Deploy ขึ้น Vercel (ฟรี)

1. Push โค้ดนี้ขึ้น GitHub ให้เรียบร้อยก่อน
2. ไปที่ https://vercel.com → New Project → เลือก repo `examonline`
3. ในหน้า Environment Variables ใส่ 3 ตัวแปรนี้ (ค่าเดียวกับใน `.env`):
   - `TURSO_DATABASE_URL`
   - `TURSO_AUTH_TOKEN`
   - `JWT_SECRET` (ตั้งค่าสุ่มยาวๆ ของตัวเอง ห้ามใช้ค่า default)
4. กด Deploy — Vercel จะรัน `api/index.js` เป็น Function หลัก (ดู `vercel.json`) ซึ่ง
   export ตัว HTTP server ตรงๆ ให้รองรับ WebSocket/Socket.IO ของห้องสอบสดได้ด้วย
   (ฟีเจอร์ WebSocket ของ Vercel ยังเป็น public beta ตั้งแต่ มิ.ย. 2026)

**ข้อจำกัดที่ควรรู้บน Vercel:**
- รูปภาพที่อัปโหลด (`/api/upload`) เขียนไปที่ `/tmp` ซึ่งไม่ถาวร จะหายเมื่อ instance
  ถูกเลิกใช้ ใช้ได้สำหรับทดลอง ถ้าจะใช้จริงควรย้ายไป object storage (เช่น Vercel Blob, S3)
- ห้องสอบสด (Kahoot) เก็บสถานะห้องไว้ใน memory ของ 1 process ถ้า Vercel กระจาย
  หลาย instance โฮสต์กับผู้เล่นอาจไปคนละ instance ทำให้ใช้งานไม่ได้แน่นอน — ถ้าฟีเจอร์นี้
  สำคัญ แนะนำให้รันเฉพาะส่วนนี้บนโฮสต์แบบ process เดียวต่อเนื่อง (เช่น Render) แทน

## โครงสร้างไฟล์

```
examhub/
  server/
    server.js   REST API + Socket.io (ห้องสอบสด)
    db.js       SQLite schema + seed
    auth.js     bcrypt + JWT + middleware
    uploads/    รูปภาพที่อัปโหลด (สร้างอัตโนมัติ)
  public/
    index.html  หน้าเว็บทั้งหมด (ดึงข้อมูลผ่าน API แทน localStorage)
  package.json
```

## สิ่งที่ยังไม่ได้ทำ / ทำต่อได้ก่อน deploy จริง (บอกไว้ตรงๆ)

1. **Google OAuth ของจริง** — ตอนนี้ใช้อีเมล+รหัสผ่านของระบบเอง เพราะ "Sign in with Google" จริง
   ต้องมี OAuth Client ID/Secret ที่คุณลงทะเบียนเองใน Google Cloud Console ผูกกับโดเมนที่ deploy จริง
   ไม่มีใครทำแทนได้ — เมื่อพร้อม เพิ่ม `passport-google-oauth20` ต่อที่ route `/api/auth/google`
   ได้เลย (auth.js เตรียมโครงไว้ให้)
2. **ระบบนำเข้าข้อสอบจากไฟล์ด้วย AI** (.docx/.pptx/.pdf/รูปภาพ → แยกโจทย์อัตโนมัติ) ของเวอร์ชันเดิม
   ยังไม่ได้ย้ายมา — ตัดออกก่อนเพื่อโฟกัสที่โครงสร้าง backend/live room/รูปภาพตามที่ขอ ถ้าต้องการ
   กลับมาทำต่อ แนะนำให้ต่อกับ **ai-router** (FastAPI middleware ของคุณเอง ที่มี fallback หลาย
   provider อยู่แล้ว) แทนการพึ่ง `window.claude` ซึ่งใช้ได้เฉพาะใน Claude Artifact เท่านั้น
3. **Rate limiting / input validation แบบเข้มงวด, HTTPS, deploy จริง** — ทดสอบเฉพาะบน localhost
   ก่อนขึ้นเซิร์ฟเวอร์จริงควรเพิ่ม reverse proxy (nginx) + TLS, `helmet`, และจำกัดอัตราการเรียก
   `/api/auth/*` กันการยิงรัว ๆ
4. **การอัปโหลดรูปภาพเก็บเป็นไฟล์บนดิสก์เซิร์ฟเวอร์เดียว** — ถ้า deploy หลายเครื่อง/serverless
   ควรย้ายไป object storage (S3 หรือใกล้เคียง) แทน

## ทดสอบแล้ว

รันทดสอบ end-to-end ระหว่างพัฒนา (ไม่ได้ส่งมาด้วย): สมัคร/ล็อกอิน, สร้าง/แก้ชุดข้อสอบ, เริ่ม–ตรวจ–ส่ง
ข้อสอบ (เฉลยไม่รั่วไปฝั่ง client), และห้องสอบสดครบวงจร (สร้างห้อง → เพื่อน join → เริ่ม → ตอบ →
เฉลย+คะแนน → จบเกม+บันทึกผล) — ทำงานถูกต้องทั้งหมด
